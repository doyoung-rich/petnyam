# 펫냠 검색 결과 UX 개선 결과

확인일: 2026-10-31. 기준 저장본: `1021f22d`. 대상: 기존 한글·영문 음식 상세 500페이지. 새 사이트·호스팅·외부 추적 서비스를 만들지 않았다.

## 기존 기능과 실제 지원 범위

|구분|기능|확인한 범위|
|---|---|---|
|A: 정상 작동·재사용|음식 검색·종별 판정·근거|5종 × 음식 50개 × 2개 언어. 기존 4단계 판정, 설명, 출처를 재사용했다. 키위·라즈베리는 별도 강아지 가이드로 유지한다.|
|A|다음 음식 검색·저장|기존 검색 폼과 동물종 변경, 최대 8개 브라우저 저장·해제를 보존했다.|
|A|동물 나이 계산기|강아지·고양이 계산과 다른 종 안내를 보존했다. 상세 페이지의 종을 계산기에서 미리 선택한다.|
|A|농사로 원료 검색|331개 원료의 성분 검색이다. 완제품 사료 분석·안전 인증이라는 명칭을 사용하지 않았다.|
|A|보호동물 공고|GitHub Actions가 만든 최근 공고 일부의 공개 JSON과 공식 사진을 재사용했다. 강아지·고양이 상세 하단에 같은 종의 `보호중` 공고 최대 3건을 표시한다.|

|B|사료 분석|현재 있는 것은 원료 성분 조회와 사료 선택 체크리스트다. 완제품의 안전·영양 적합성·회수 여부를 판단하는 분석기는 없다.|
|C: 구현되지 않음|커뮤니티·개인 등록 조회·완제품 사료 분석|게시·댓글·회원 기능이나 완제품 분석 결과가 있는 것처럼 표시하지 않았다.|
|C|외부 방문 분석 대시보드|기존 GA 등 별도 분석 설치를 찾지 못했다. 새 추적 서비스를 설치하지 않았다.|

## 구조와 변경 파일

운영 배포본은 GitHub `main`의 `/docs` 정적 파일이다. `scripts/prepare-github-pages.mjs`가 생성 과정을 실행하고, `docs/food-page-content.js`가 정적 생성과 브라우저 보완에 함께 사용되는 실제 상세 화면 원본이다. 음식 설명은 종별 JS 데이터이며 별도 검색 데이터베이스를 새로 도입하지 않았다. 기존 `app/`의 프레임워크 초안은 현재 Pages 배포 경로가 아니므로 이번 작업에서 배포 방식으로 전환하지 않았다.

|파일|역할|
|---|---|
|`docs/food-page-content.js`|핵심 판정·위험 경고 → 콘텐츠 바로가기 → 요약 → 상세·출처 → 관련 음식 → 종별 기능 → 하단 공고 순서의 공통 렌더러|
|`docs/result-experience.css`|PC 읽기 영역·보조 패널, 모바일 단일 열, 텍스트·아이콘 판정, 초점 표시|

|`.github/workflows/normalize-pages.yml`|기존 배포 준비 검사에 신규 검사 추가|

## 이전과 이후

|이전|이후|
|---|---|
|긴 설명을 순서대로 읽어야 핵심 조건을 확인|손질·급여 조건 / 피할 형태·상황 / 이미 먹었다면을 먼저 요약하고 해당 상세로 연결|
|비슷한 모양의 카드가 반복|판정 카드, 요약 띠, 구분선 중심 본문, 관련 음식·서비스 카드로 계층 구분|
|관련 음식이 두 영역에서 반복|기존 검색 폼과 같은 종의 4개 관련 음식을 한 영역으로 통합|
|일반적인 관련 링크|종별 안내 3개 이하와 공통 콘텐츠 바로가기 4개. 계산기 지원 범위와 원료 성분 자료의 한계를 명시|
|상세 결과에서 기존 도구 발견이 어려움|강아지·고양이 계산기, 농사로 원료 검색, 관련 이야기·가이드로 연결|
|보호동물 공고는 홈 중심|강아지·고양이의 안전 설명 아래에서 같은 종 공고·공식 출처·수집 시각 확인|

기존 안전 판정 값을 바꾸거나 급여량·횟수·효능을 새로 만들지 않았다. 앵무새 채소 안내의 잘못된 조사(예: “고구마은”)만 교정했다.

## 검증 결과

- 음식 상세 500페이지의 기존 상태·답변·이유·준비·피할 상황·출처 유지, 고유 H1·ID, 실제 내부 목적지, 관련 음식 중복 제거 검사 통과.
- 기존 검색, 종 변경, 저장·해제·목록 복원·저장 불가 상황 검사 통과.
- PC 1265px와 모바일 390px 화면에서 가로 넘침 없음. 본문 이동, 위험 경고, 종별 추천, 저장·복사 동작을 브라우저에서 확인.
- 고양이 상세 → 계산기에서 고양이 선택 및 계산 결과 확인. 영문 햄스터 우유의 정보 부족 판정과 지원 범위 확인.
- 보호동물 사진의 공식 호스트와 실제 표시 확인. 공고는 입양 가능 확정이 아닌 수집 시점의 보호 상태임을 안내한다.
- 하단 공고가 보이기 전 요청하지 않으며 동시 호출을 1개로 공유하고 5분 동안 재사용한다. 외부 기관 API를 브라우저에서 직접 호출하지 않는다.
- 공고 호출 실패를 모의 실행해 이전 표시 자료 유지와 대체 안내를 확인했다. 수집 목록이 비었을 때는 공식 전체 공고로 연결한다.
- 기존 나이·비용 계산, 농사로 검색, 운영자 글, 홈 공고, 제휴 추천 중지 상태의 회귀 검사 통과.
- 536개 사이트맵 URL, 537개 전체 HTML의 제목·canonical·언어·구조화 데이터 검사 통과. 핵심 본문과 내부 링크는 정적 HTML에 있어 자바스크립트 없이도 읽을 수 있다.
- 앵무새 고구마 HTML은 12,391 → 18,050바이트, 음식 상세 평균 18,653바이트·최대 24,451바이트. 검색용 새 라이브러리나 서버 요청을 추가하지 않았고, 공고 사진은 지연 로딩한다. 실제 공개 환경의 Core Web Vitals·방문자 체류시간·순위 개선까지 검증한 결과는 아니다.
- API 인증키·개인 등록번호·소유자 정보는 공개 파일에 추가하지 않았다. 기존 API 설정과 AdSense 설정은 변경하지 않았다.

## 측정과 남은 한계

`petnyam:interaction`이라는 페이지 내부 이벤트에 결과 열람·관련 음식·원료 검색·나이 계산기·공고·등록 안내·관련 콘텐츠 선택을 구분했다. 이벤트에는 허용된 종·음식 식별자·언어만 포함한다. 자유 입력 검색어나 URL의 질의문은 포함하지 않는다. 네트워크 전송·자동 저장·새 추적 서비스가 없어, 현재 방문 통계가 실제로 수집되거나 대시보드가 만들어진 것은 아니다.

완제품 사료 분석, 공개 개인 등록 조회, 커뮤니티, 수의사 감수는 이번 작업에서 새로 구현하지 않았다. 영어 사용자가 한국어 전용 기존 가이드로 가는 경우 링크에 `(Korean)`을 표시한다.

## 배포 상태

첨부 요청의 “운영환경 배포처럼 되돌리기 어려운 작업은 사전 승인을 받아라” 조건에 따라 `main`에 병합·배포하지 않았다. 수정본은 별도 검토 브랜치로 보관하며 승인 후 최신 `main`과 결합하고 기존 GitHub Pages `/docs` 방식으로 배포해야 한다.
